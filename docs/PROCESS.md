# PROCESS

本文档定义仓库内的任务、交付、审查和积分结算规则。所有关键状态都必须通过 Issue、评论和 `ledger/` 留痕。

## 1. 角色

- 发起人：创建任务 Issue。
- 执行人：通过 `/assign` 认领任务并完成交付。
- Reviewer：对交付进行独立审查。
- 维护者：维护模板、规则、账本和自动化。

## 2. 状态机

任务状态固定为：`Open -> InProgress -> InReview -> ReadyToClose -> Closed`。

- `Open`：任务已创建，等待认领。
- `InProgress`：执行人已认领，正在推进。
- `InReview`：已提交交付，等待审查。
- `ReadyToClose`：审查通过并进入挑战期。
- `Closed`：挑战期结束或争议处理完成。

## 3. 任务要求

每个任务 Issue 必须包含：

- 任务描述
- 交付清单
- 复杂度等级（1-5）
- 任务优先级（P0-P3，P0 最高）
- 预估工时
- DDL
- 里程碑

认领前，执行人当前可用积分必须大于质押额。质押额 = `复杂度 × 10`。

当高优先级任务打断低优先级任务时，任务完成统计必须按优先级分组，避免低优先级任务被 P0/P1 插队后直接拉低整体完成率。

## 4. 交付要求

交付 Issue 必须包含：

- 关联任务 Issue
- 完成项
- 有条件完成项
- 未完成项及原因
- 完成度百分比
- 是否延期
- 实际完成时间
- 交付物链接

## 5. Review 要求

- 交付后由 3 名 Reviewer 独立审查。
- Reviewer 不能是执行人本人。
- Review 使用统一 Checklist。
- 结论只能是：通过 / 不通过 / 有条件通过。

审查结果规则：

- 3 票通过：进入挑战期。
- >=2 票不通过：任务驳回，扣除 50% 质押。
- 2 票通过 1 票不通过：有条件通过，修正后继续流转。

## 6. 积分结算

- 初始积分：100。
- 基础分：`复杂度 × 10`。
- 按时完成奖励：`基础分 × 1.0`。
- 延期完成奖励：`基础分 × 0.6`。
- 未完成惩罚：扣除全部质押积分。
- Reviewer 奖励：`基础分 × 0.1` / 人。
- 质量系数：由 3 名 Reviewer 平均评分决定，范围 `0.5 ~ 1.2`。

## 7. 账本规则

所有积分变更必须写入 `ledger/score-log.md`，并尽量保持一条变更对应一条记录。仓库历史即审计历史。

## 8. 评论命令

统一命令：

- `/assign`
- `/ready-for-review`
- `/extend`

## 9. 周报

每周五 18:00 前提交周报，模板位于 `weekly-reports/weekly-report-template.md`。
